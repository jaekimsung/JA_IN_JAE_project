# 실험 설계

**주제: K-CITY 복합 교통 환경에서 전문가 사전학습의 효과와 한계 분석.** 설정은 [experiment.json](../configs/kcity/experiment.json)에 있습니다.

## 연구 질문

| 질문 | 비교 |
|---|---|
| RQ1. BC 초기화가 목표 성능까지 필요한 PPO 경험을 줄이는가? | B2 vs B3: 같은 전이 수에서의 dev 곡선, 목표 도달 전이 수, 1M 시점 성능, 전문가·BC 비용을 포함한 총비용 |
| RQ2. 교통 수요가 늘어도 그 이점이 유지되는가? | 고정 정책을 600·900·1200대/h에서 평가. 과제별 실패 유형·시간·HV 노출 |
| RQ3 (선택). 같은 양의 전문가 데이터에서 상황 구성이 영향을 주는가? | 자연 분포 vs 상호작용 균형 표본 |

BC와 PPO의 결합 자체를 새 알고리즘으로 주장하지 않습니다. "초기에만 유리함", "역효과", "차이 없음"도 연구 질문에 대한 유효한 답입니다. 일반화의 범위는 같은 K-CITY 도로망에서의 수요 변화로 한정합니다.

## 실행 순서와 예산

| 단계 | 내용 |
|---|---|
| 전문가 pool | B0로 최소 1M 전이 수집(성공·실패 모두 저장) |
| BC view | 성공 Episode에서 train 200k / val 50k 고정 |
| BC (B1) | seed 11·22·33, 각 10k update, val 최저 checkpoint |
| PPO (B2, B3) | 방법 × seed마다 정확히 1M 전이(총 6M), 50k마다 dev 평가 |
| 최종 평가 | 고정된 정책으로 final 패널 실행: B0 300 + B1·B2·B3 2,700 = 3,000 Episode |
| 최종 정책 수집 | 1M 시점 PPO 정책 6개 × 500k = 3M 전이 |

## 평가 패널

[configs/kcity/panels/](../configs/kcity/panels/)

- **dev:** 100개 사례(A 30 / B 30 / C 40), 수요 1.0배. 학습 중 곡선과 목표 도달 판정에만 씁니다.
- **final:** 수요 1.0·1.5·2.0배 × 100개 사례. 최종 정책이 고정된 뒤에만 실행하며, 모델이나 설정 선택에 쓰지 않습니다.
- dev와 final의 사례는 서로 겹치지 않으며, 수요 배수별로 같은 교통 seed를 공유합니다.

## 지표

[evaluation/metrics.py](../kcity/evaluation/metrics.py)

| 지표 | 정의 |
|---|---|
| 완주 (completion) | 올바른 목적지·경로로 300초 안에 도착 |
| **규칙 준수 완주** (주 지표) | 완주 + AV 충돌 없음 + 적색 진입 없음. 신호 판정 불가가 하나라도 있으면 집계하지 않음(None) |
| Collision Rate | 충돌 Episode / 유효 Episode (Wilson 95% 구간 함께 보고) |
| 신호 준수 | 1 − 적색 진입 / 판정 가능한 신호 통과 |
| 시간 | 완주 Episode의 평균 시간, 실패를 300초로 둔 penalized time |
| 정지·대기 | 정지 시간(평균·최대·60초 초과 사례 수), 기한 초과 수, 평균 속도, 선행차 간격 |
| 교통 노출 | 출발 시 HV 수(10대 미만 사례 수), 최소 HV 수, 시간가중 평균 HV 수, AV 50m 안 HV 수(시간가중 평균·최대·1대 이상 있었던 시간 비율), 선행차 존재 비율 |
| 목표 도달 전이 수 | dev 100에서 규칙 준수 완주율 ≥ 0.80이 연속 2회 처음 나온 전이 수. 1M까지 없으면 right-censored |

정책 실패(기한 초과·충돌 등)는 유효 분모에 남깁니다. 연결 오류 같은 인프라 실패만 따로 집계합니다.

## 예비 실험(pilot) 결과

seed 11·22·33에서 BC 1,000 update, B2·B3 각 50k 전이로 학습했고, 같은 dev 100 사례로 평가했습니다. 9개 정책 모두 100/100 완주했으며 충돌과 적색 진입은 0이었습니다. 원자료는 [SUMMARY.json](research_checks/KC-SETTINGS-20261115-01/SUMMARY.json)입니다.

| seed | BC 평균 완주(s) | PPO-only 평균(s) | BC→PPO 평균(s) |
|---|---:|---:|---:|
| 11 | 58.248 | 57.530 | 57.620 |
| 22 | 58.278 | 57.586 | 57.720 |
| 33 | 58.193 | 57.563 | 57.625 |

BC는 학습 0전이 시점에 이미 완주 능력이 있었지만, 중간 checkpoint에서 필수 차선 변경을 놓치는 실패가 나타났습니다. 진단 결과 결정적 argmax가 "유지"를 고른 것이 원인이었습니다. 이 정도의 작은 시간 차이로 방법의 우월성을 결론 내리지 않습니다.

## 해석의 범위

- 결과는 SUMO 안전 기능(31/512)을 포함한 시스템 성능이며, AV 단독 안전성이나 실차 안전을 뜻하지 않습니다.
- 정지·양보 규칙 준수와 부당한 대기의 원인은 판정하지 않습니다.
- 교통 수요는 합성입니다. 사례마다 HV 노출이 다르며, 노출이 낮은 사례도 제외하지 않고 함께 보고합니다.
- 결과를 본 뒤 oversampling, 보상, mask, 하이퍼파라미터를 바꾸지 않습니다.
