# 주행 환경

자율주행 차량(AV)이 K-CITY 도로망에서 일반 차량(HV)·교통신호와 상호작용하며 정해진 경로를 따라 목적지까지 주행하는 Gymnasium 환경입니다. 구현은 [env/](../kcity/env), 맵 자산은 [maps/kcity/](../maps/kcity/README.md), 환경 계약은 [configs/kcity/v1/](../configs/kcity/v1/README.md)에 있습니다.

## 도로와 교통

| 항목 | 내용 |
|---|---|
| 도로망 | CARLA K-CITY OpenDRIVE를 SUMO로 변환. 일반 Edge 176개, 일반 차선 198개, 교차로 내부 차선 346개 |
| 교차로 | 수요 감응식 신호 14곳, 전방향 정지 규칙 2곳, 회전교차로 포함 |
| 일반 차량 | 네트워크 전체 요청 수요 600대/h(Poisson), Krauss·IDM·EIDM·ACC 4종 동일 비율, 정지 상태에서 투입 |
| 평가 수요 | 1.0배·1.5배·2.0배(600·900·1200대/h) |
| warmup | AV 투입 전 60초 동안 교통을 먼저 흘림 |
| 시각화 | 가상 건물·가로수·녹지(충돌 대상 아님), 선택형 항공사진 배경 |

교통 흐름 검증(기본·2배·3배 수요, 무작위 출발·도착, 각 3 seed)에서 2,124/2,124대가 도착했고 충돌·텔레포트는 0건이었습니다. 신호 설계와 차선 정리 근거는 [맵 문서](../maps/kcity/README.md)와 [신호 설계 보고서](../maps/kcity/reports/SIGNAL_DESIGN.md)에 있습니다.

## 주행 과제

| 시나리오 | 경로 | 핵심 의사결정 |
|---|---|---|
| A (신호) | `-68 → -13 → -71` | 신호 교차로 접근·정지·재출발 |
| B (필수 차선 변경) | `-3#4 → … → -68` (6개 Edge) | 출발 도로에서 다음 경로로 이어지는 차선(lane 1)으로 변경 |
| C (복합) | 17개 Edge, 신호 4곳 | 필수 차선 변경 + 연속 신호 교차로 |

모든 과제는 출발 위치 5m·속도 2m/s에서 시작하고 제한 시간은 300초입니다. 학습·수집 사례는 A/A/A/B/B/B/C/C/C/C 순서로 반복합니다. 사례(case)마다 교통·투입 seed가 정해져 있어 같은 사례는 같은 교통으로 재현됩니다.

## 시간과 제어

- 정책은 0.5초마다(2Hz) 행동을 결정하고, SUMO는 0.1초 tick을 5번 진행합니다. 사건이 생기면 1~5 tick 사이에서 끝날 수 있습니다.
- 가속은 `setAcceleration`으로 적용합니다. 정규화 값 +1은 +2.0 m/s², −1은 −4.5 m/s²이고, AV 속도 상한은 8.33 m/s(30km/h)입니다.
- 차선 변경은 1초 동안 요청하며 이후 1초 cooldown이 있습니다.
- SUMO 안전 기능(speedMode 31, laneChangeMode 512)이 켜져 있습니다. 따라서 결과는 SUMO 안전 보정을 포함한 시스템 성능입니다.

## 관측 (73차원, `[-1, 1]`)

[env/observation.py](../kcity/env/observation.py). 주변 차로 5개(왼쪽 2·왼쪽 1·현재·오른쪽 1·오른쪽 2)를 같은 형식으로 봅니다.

| index | 의미 |
|---|---|
| 0 | AV 속도 / 8.33 |
| 1–20 | 차로별 [앞차 간격/100m, 앞차 상대속도, −뒤차 간격/50m, 뒤차 상대속도] (차가 없으면 1, 0, −1, 0) |
| 21–25 | 차로가 경로와 연결되는지 (없는 차로는 −1) |
| 26–30 | 차로 점유 밀도 |
| 31–40 | 차로별 앞차·뒤차 존재 여부 |
| 41–45 | 차로 존재 여부 |
| 46–50 | 차로 번호, 경로 진행률, 남은 경로 거리/1000m, 현재 차로 남은 길이/100m, 현재 가속도 |
| 51–53 | 교차로 내부 여부, 차선 변경 cooldown, 남은 시간 비율 |
| 54–59 | 100m 안 다음 신호 존재·거리·상태(적/황/녹/소등) |
| 60–62 | 정지 규칙 존재·거리, 비신호 규칙 존재 |
| 63–67 | 다음 연결 방향(좌/직/우/유턴), 현재 Edge 끝까지 거리 |
| 68–71 | 왼쪽·현재·오른쪽 차로가 다음 경로와 연결되는지, 경로 정보 유효 여부 |
| 72 | 현재 차로 제한속도 / 8.33 |

정책은 이 73차원만 받습니다. 데이터에는 모든 차량의 절대 위치·속도·차선을 담은 전체 State가 따로 기록됩니다.

## 행동

`[가속, 차선 명령]`. 가속은 [-1, 1]로 잘라 m/s²로 변환합니다. 차선 명령은 0.5 이상이면 왼쪽, −0.5 이하면 오른쪽, 그 사이면 유지입니다. 차선이 없거나, 교차로 내부이거나, cooldown 중인 요청은 거부하고 그 이유를 기록합니다. 정책은 같은 조건으로 계산한 차선 mask `[왼쪽, 유지, 오른쪽]`을 사용합니다.

## 보상

| 항목 | 값 |
|---|---|
| 경로 진행 | max(0, 진행 거리 증가) / 10 (도착 시 남은 거리 포함) |
| 도착 | +10 |
| 충돌 | −20 |
| 적색 신호 진입 | −10 |
| 거부된 차선 요청 | −0.02 |
| 실제 차선 변경 | −0.01 |

## 종료

도착, 충돌, 적색 진입, 경로 이탈, 텔레포트, 차량 제거, 300초 기한 중 하나가 일어나면 `terminated=True`입니다. 남은 시간이 관측에 들어 있으므로 기한 초과도 종료로 처리합니다. 매 0.1초 tick마다 충돌, 적색 진입(신호 link 기준), 실제 차선 변경, 도착, 텔레포트, 경로 이탈을 이벤트로 기록합니다.

## 한계

- 교차로를 가로지르는 차량을 위한 관측 슬롯이 없습니다(기록은 됨). 가림·센서 잡음도 모델링하지 않습니다.
- 정지·양보 규칙 준수를 완전히 판정하지 않습니다. 지원하는 규칙 판정은 적색 진입입니다.
- 기본 수요에서는 사례에 따라 출발 시점 지도 전체 HV가 5~7대로 적을 수 있습니다.
