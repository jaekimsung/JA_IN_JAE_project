# 실험 설계

**주제: K-CITY의 세 가지 의사결정 상황에서 BC의 한계를 사전 데이터를 쓰는 강화학습(RLPD)으로 해결할 수 있는가.** 설정은 [experiment.json](../configs/kcity/experiment.json)에 있습니다.

## 문제 상황

도로 구조에서 생기는 상호작용과 AV의 결정은 [ENVIRONMENT](ENVIRONMENT.md#세-가지-주행-과제)에 있습니다. 상황별 측정은 [evaluation/situations.py](../kcity/evaluation/situations.py)가 합니다.

| | 상황 | 시나리오 | Episode마다 기록하는 값 |
|---|---|---|---|
| ① | 연속 감응식 신호 통과 | A | 신호 통과 수, 적색·황색 진입 수, 적·황 신호 50m 안에서 정지한 시간, 신호 교차로 안에서 정지한 시간 |
| ② | 혼잡 속 필수 차선 변경 | B | 차선 변경 성공 여부와 위치(m), 요청·거부 수, 차로 끝에서 정지한 시간, 목표 차로의 HV 수 |
| ③ | 비신호 교차로에서 양보 | C | 교차로 통과 수, 다른 차량과 같은 교차로 안에 있었던 통과 수, 그때의 최소 거리, 양보 위반 수, 교차로 충돌 수 |

완주하지 못한 Episode는 끝난 위치로 실패 상황(`failure_situation`)을 분류합니다.

## 가설

| | 가설 | 확인하는 값 | 비교 |
|---|---|---|---|
| H1 | BC는 전문가 행동을 평균적으로 따라 하지만, 정지·출발 시점이 조금만 어긋나도 실패하는 상황(적색·황색 정지, 양보)에서 오차가 누적된다 | 방법별·상황별 실패율과 실패 유형 | B0 vs B1 |
| H2 | 사전 데이터 없는 강화학습은 같은 예산에서 "기다리면 안전하다"에 머물거나 규칙 위반으로 끝나는 Episode가 많다 | 기한 초과 수, 정지 시간, 위반 수, dev 곡선 | B2 vs B3 |
| H3 | 사전 데이터를 매 batch에 섞는 RLPD는 적은 환경 경험으로 BC보다 높은 규칙 준수 완주율에 도달한다 | dev 곡선의 시작·최저·최종 값, 목표 도달 전이 수, final 패널 성능 | B1 vs B3 |

`runner/report.py`가 이 값들을 방법별로 나란히 출력합니다. 우열을 판정하지는 않으며, "차이 없음"이나 "역효과"도 유효한 답입니다.

## 실행 순서와 예산

| 단계 | 내용 | 전이 수 |
|---|---|---:|
| 전문가 pool | B0로 수집(성공·실패 모두 저장) | 4,000,000 이상 |
| BC view | 규칙 준수 완주 Episode에서 학습 20만 / 검증 5만 행 고정 | – |
| BC (B1) | seed 11·22·33, 각 20,000 update, 검증 손실 최저 checkpoint | – |
| RL (B2, B3) | 방법 × seed마다 300,000 전이, 25,000마다 dev 평가. B3는 전문가 pool 100만 전이를 사전 데이터로 사용 | 1,800,000 |
| 최종 평가 | 고정된 정책으로 final 패널 실행 | – |
| 최종 정책 수집 | 예산 종료 시점 RL 정책 6개 × 700,000 | 4,200,000 |

합계 10,000,000 전이 이상입니다.

## 평가 패널

[configs/kcity/panels/](../configs/kcity/panels/)

- **dev:** 100개 사례(A 30 / B 30 / C 40), 수요 1.0배. 학습 중 곡선과 목표 도달 판정에만 씁니다.
- **final:** 수요 1.0·1.5·2.0배 × 100개 사례. 최종 정책이 고정된 뒤에만 실행하며, 모델이나 설정 선택에 쓰지 않습니다.
- dev와 final의 사례는 서로 겹치지 않으며, 수요 배수별로 같은 교통 seed를 공유합니다.

## 지표

[evaluation/metrics.py](../kcity/evaluation/metrics.py)

| 지표 | 정의 |
|---|---|
| 완주 (completion) | 올바른 목적지·경로로 300초 안에 도착 |
| **규칙 준수 완주** (주 지표) | 완주 + AV 충돌 없음 + 적색 진입 없음 + 양보 위반 없음. 신호 판정 불가가 하나라도 있으면 집계하지 않음(None) |
| Collision Rate | 충돌 Episode / 유효 Episode (Wilson 95% 구간 함께 보고) |
| 신호 준수 | 1 − 적색 진입 / 판정 가능한 신호 통과 |
| 시간 | 완주 Episode의 평균 시간, 실패를 300초로 둔 penalized time |
| 정지·대기 | 정지 시간(평균·최대·60초 초과 사례 수), 기한 초과 수, 평균 속도, 선행차 간격 |
| 상황별 지표 | 문제 상황 ①②③의 노출 Episode 수, 실패 수·실패율·실패 유형과 상황별 측정값 |
| 교통 노출 | 출발 시 HV 수, 시간가중 평균 HV 수, AV 50m 안 HV 수, 선행차 존재 비율 |
| 목표 도달 전이 수 | dev 100에서 규칙 준수 완주율 ≥ 0.80이 연속 2회 처음 나온 전이 수. 예산 안에 없으면 right-censored |

정책 실패(기한 초과·충돌·위반 등)는 유효 분모에 남깁니다. 연결 오류 같은 인프라 실패만 따로 집계합니다.

## 해석의 범위

- SUMO는 AV의 가감속 한계만 적용합니다(speedMode 6, laneChangeMode 0). 앞차 간격·신호·양보·차선 변경 간격은 모두 정책이 결정하며, 실차 안전을 뜻하지는 않습니다.
- 교통 수요와 상호작용 차량 흐름은 합성입니다. 실제 K-CITY 교통량이 아닙니다.
- seed는 3개입니다. 작은 차이로 방법의 우열을 결론 내리지 않습니다.
- final 패널 결과를 본 뒤 보상·하이퍼파라미터·모델 선택을 바꾸지 않습니다.
