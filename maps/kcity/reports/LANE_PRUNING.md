# 미사용 차선 제거 결과

기준은 현재 177대 합성 교통의 seed 0/1/2 통행 기록이다. 실제 K-CITY에서 쓰지 않는 차선이라는 뜻은 아니다.

- 최초 일반 미사용 15개와 내부 미사용 56개를 식별했다. 내부 차선의 부모 회전 연결 53개를 삭제했다.
- 연결 삭제 후 `-51_0`, `-51_2`도 세 seed 모두 점유·진출입·차선변경 이벤트 0이 되어 추가로 삭제했다.
- **일반 차선 215→198개(17개 삭제), 내부 차선 419→362개.** 내부 미사용 56개 제거와 함께 교차로 재계산으로 분할 차선 수가 추가로 1개 줄었다.
- 일반 도로 Edge 176개와 차량 177대의 ID·모델·경로·출발 시각은 유지했다. `kcity.rou.xml`은 삭제 전과 바이트 단위로 동일하다.
- 데모 및 비교용 네트워크 모두 같은 차선·회전 삭제 정책을 적용했다. 아래 교통 검증은 데모 프로필의 결과다.
- 최종 3개 seed에서 **531/531대 도착, 충돌·텔레포트 0, 남은 미사용 차선 0개**. 각 차선은 세 seed 중 적어도 한 번 점유 또는 차량 이벤트가 있어야 사용으로 판단한다.
- 급제동 경고는 seed별 10/15/17건 남는다. 모든 교통량·경로에서의 안전성이나 승차감 검증은 아니다.

## 연결·형상·원본 경로의 한계

[SUMO PlainXML 패치](https://sumo.dlr.de/docs/Networks/PlainXML.html)를 netconvert에 입력해 차선과 회전 연결을 삭제했다. netconvert가 차선 인덱스·교차로 내부 연결·우선권·신호 인덱스를 함께 재계산했다. 예상한 연결 집합과 결과가 정확히 같은지 검사해 삭제한 회전이 자동으로 복원되지 않았음을 확인했다.

이 과정에서 36개 일반 차선의 배치·교차로 접속부 형상이 재계산됐다. 유지 차선의 원본 `origId`는 보존했지만 모든 좌표가 삭제 전과 같지는 않다. `../audit/pruning_kcity.net/report.json`에 전후 형상과 차선 ID 매핑을 기록했다. 합성 신호 2곳은 50초 주기를 유지한다.

qualifier 원본 499점 중 38점은 삭제 대상 `3#4_0`에 대응했다. 원본 매칭은 `build.json`의 `baseline_lane`에 남기고 삭제 상태를 표시했다. SUMO 데모는 기존 Edge 경로를 따르며 원본 CSV의 차선을 그대로 강제하지 않는다. 원본 내부 도로 ID 42개가 이번 정책으로 추가 제외됐고, 기존 import 누락 22개와 따로 기록했다.

## 재현 및 증거

- `../lane_pruning.json`: 삭제 대상, 원본 식별자, 기준 네트워크·경로 해시.
- `../audit/before_remove_unused_lanes/`: 삭제 전 맵·경로·검사 결과 백업.
- `../audit/pruning_kcity.net/`: 최종 데모 삭제 패치, 변환 로그, 전후 차선 매핑.
- `lane_usage_after_pruning_round1/`: 첫 삭제 후 추가 미사용 2개를 식별한 검사.
- `lane_usage_after_pruning/summary.json`: 최종 모든 차선 통행 여부 및 네트워크·경로 해시.
- `validation_kcity.json`: 최종 완주·충돌·텔레포트 검사.

python scripts/kcity/build.py
